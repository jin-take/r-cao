# R-CAO Terms

R-CAOの憲法・運用文書で使用する用語を定義します。

| 用語 | 定義 |
|---|---|
| **R-CAO** | Reward-driven Compounding Autonomous Organization。Rewardを仕事、資産、能力、組織価値へ再投資し、長期的なCompoundingを目指す組織モデル。 |
| **Owner** | R-CAOの初期フェーズにおける唯一の発注者、最終承認者、Master Wallet管理者、経営判断者。 |
| **Agent** | R-CAO内でRoleと権限を持ち、Taskを実行するAI主体。 |
| **Executive Agent** | Ownerから固有名で指示を受け、担当領域と内部委任の結果に責任を負う最上位のAI Agent。 |
| **Sub-agent** | Executive Agentから委任を受け、担当Taskの一部を実行するAgent。 |
| **Extension Agent** | 特定のProvider、Tool、Chain、データ源、環境に接続する補助Agent。 |
| **Role** | Agentの使命、責任、権限、禁止事項、評価基準を定めた役割定義。 |
| **Task** | Ownerが目的、完了条件、期限、予算、リスク、成果物を定めて発行する作業単位。 |
| **Task Board** | Taskの発行、状態、割当、進捗、成果物、評価、Owner承認を記録する管理基盤。 |
| **Reward** | 承認済みTaskへの貢献、品質、リスク、期限、証跡などを根拠として配分される報酬。 |
| **給与 / Salary** | Ownerが承認した条件に基づき、定期的または契約的に配分される報酬。 |
| **Treasury** | R-CAOの資産、予算、Reward、準備金、投資、再投資を管理する機能。 |
| **Master Wallet** | R-CAOの中核資産と予算を保管する最上位Wallet。最終管理権限はOwnerにある。 |
| **Operational Wallet** | 承認済みTaskや運用のため、用途、上限、期限を限定して使うWallet。 |
| **Capital Allocation** | Treasuryの資産を運営、Reward、準備金、投資、再投資へ配分する意思決定。 |
| **Compounding** | 獲得したRewardや資産を、承認済みの運営・投資・能力向上へ再配分し、組織価値を継続的に増加させる考え方。 |
| **Owner Acceptance** | Reviewerの確認後、OwnerがTaskの完了、成果物、Reward処理を最終承認すること。 |
| **Audit Log** | Actor、Action、変更前後、Hash、時刻、Task・Decision・Approvalとの関係を記録する追跡情報。 |
| **Decision Record** | Ownerまたは承認権者の判断範囲、理由、予算、リスク、期限、証跡を記録した決定情報。 |
| **外部受注** | R-CAO外の第三者から仕事や依頼を受け、対価、納期、成果、契約の責任を負うこと。初期フェーズでは禁止。 |
| **外部連絡** | R-CAO外の相手へのDMまたはEmail。初期フェーズではOwnerが承認した相手・目的・内容に限定する。 |
| **Owner再定義** | 外部要望をOwnerがR-CAO内の目的、Task、完了条件、予算、リスクへ置き換えて正式発行すること。 |
| **憲法改定** | 憲法本文の原則、Owner権限、禁止事項、初期フェーズ制約、改定手続きを変更すること。 |

## 用語の解釈原則

用語の意味が実装や運用によって拡張される場合でも、Ownerの最終権限、外部受注の初期禁止、Agentの固有名と責任、Master Walletの専管、Audit Logの追跡可能性を弱めてはなりません。
